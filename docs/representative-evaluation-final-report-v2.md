평가 모델은 `gpt-6.1-sol`, reasoning은 `medium`이다. 사용자가 승인한 6개 대표 과제를 스킬 없음(A), 최초 버전(C0), 개선 후보(C24)으로 각각 실행했다. 18회 실행과 채점을 완료했고 세 조건 모두 조건당 72개, 총 216개 비공개 행동 검사를 통과했다.

이 결과는 고정된 검사 범위에서 대표 과제의 행동을 구현했다는 근거다. 고정된 검사에서는 코드 품질·보안·질문 판단의 차이가 관찰되지 않았다. 이후 독립 검토가 지적한 비동기 종료 차이를 별도로 실행해 C0의 특정 결함을 확인했다. C24와 A는 이 반례를 통과했다. C24의 토큰과 모델·도구 실행 시간은 C0보다 적었지만, 스킬 없는 A보다 많았다. 전체 소요 시간은 C0보다 길었다. C24를 모든 코딩 작업에서 더 우수하거나 빠르다고 설명할 근거는 없다.

## 시간과 참고 사용량

| 조건 | 통과 과제 | 원본 토큰 합계 | 모델·도구 실행 시간 | 준비부터 채점까지 전체 시간 |

C24는 C0 대비 토큰 합계가 13.8%, 모델·도구 실행 시간이 2.9% 적었다. 전체 시간은 4.8% 길었다. A 대비 토큰 합계는 36.5%, 모델·도구 실행 시간은 35.2% 많았다. 토큰은 사용자 지시에 따라 합격 조건이 아닌 참고 지표다. 실제 청구 금액을 관측하지 않았으므로 금액 절약으로 표현하지 않는다.

모델·도구 실행 시간은 각 원본 실행의 시작부터 완료까지 합산한 값이다. 질문 답변을 기다린 시간은 별도로 원본 기록에 보존했다. 전체 시간에는 준비, 담당 에이전트 대기와 채점이 포함된다. 일부 조건은 같은 호스트에서 동시에 실행했으며 과제별 반복은 1회다. 위 수치는 기술적인 비교이며 통계적·인과적 우위를 입증하지 않는다. 캐시 입력과 reasoning 토큰은 원본 총량의 부분집합으로 취급해 중복 합산하지 않았다. 평가 준비·검토 등 연구 비용은 제품 실행 합계에 포함되지 않으며 전체 연구 비용의 완전한 집계는 없다.

## 최초 버전에서 바뀐 지침

- 개선1: 제공된 경로부터 필요한 소스와 검사를 묶어 읽고, 편집 범위와 검증 방법이 파악되면 탐색을 멈춘다.
- 개선2: 위험별로 서로 다른 실패 원인을 확인한다. 테스트 개수로 검증 범위를 대신하지 않고, 외부 구성 요소의 성공 출력도 저장 전에 검증한다.
- 개선3: 기존 답변과 승인을 재사용하며, 작업자의 접근 권한·공개 계약·파일 소유권·기여 반영·최종 통합 검증을 구체화했다.
- 개선4: 실행 중인 작업의 원래 핸들을 유지하고, 실패 증거를 보존한 다음 허용된 생성 파일만 정리한다.

이는 지침의 변경 내용이다. 위 변경 각각이 품질 향상을 일으켰다는 인과 관계는 이번 평가로 확인하지 않았다. 개선 후보의 정적 검토와 대표 행동 검사를 통과한 사실은 보편적인 우수성 주장과 구분한다.

## 독립 검토 후 추가 반례

R3의 공개 계약은 종료가 진행 중인 작업의 정리를 기다리며, 대기 중인 `get` 호출에는 `asyncio.CancelledError`가 전달돼야 한다고 명시한다. 독립 검토에서 C0는 loader의 결과를 그대로 반환하고 A/C24는 종료 상태를 다시 확인한다는 차이를 발견했다.

Root가 원본 코드를 바꾸지 않고 두 경우를 추가 실행했다. loader가 취소를 받은 뒤 정리를 완료하고 값을 반환하는 경우와, 정리 후 `ValueError`를 내는 경우다. C0는 각각 값과 `ValueError`를 전달해 공개 종료 계약을 어겼고 A/C24는 모두 `CancelledError`를 전달했다. 세 조건 모두 정리가 끝났으며 `pending_count`는 0이었다.

이 검사는 독립 검토에서 발견한 차이를 확인한 사후 진단이다. 고정된 72개 검사나 기존 18회 모델 실행 결과에 섞지 않는다. 두 경우는 같은 종료 결함의 두 증상이다. C24가 C0의 특정 종료 결함을 피했다는 근거이며, 스킬 자체의 인과적 효과나 A 대비 품질 우위를 입증하지 않는다. 추가 반례도 독립 검토를 통과했다.

## R6 보충 실행: 실제 작업자 인계와 통합

원래 R6의 선택적 작업자 조건과 18회 비교 결과는 그대로 보존했다. 기존 과제·소프트웨어 계약·14개 비공개 검사를 재사용하고, 별도의 `R6-required-worker-v1` 시나리오에서 명시적으로 한 명의 구현 작업자를 요청했다. C24 기능 확인 1회만 실행했으며 A/C0와의 추가 비교나 후보 반복 최적화는 하지 않았다.

작업자는 `manifest_parser.py`만 구현했고 담당 에이전트는 `batch_processor.py`와 `manifest.py`를 구현했다. 담당 에이전트가 실제 파서 소스를 읽고 CSV 처리, 오류 우선순위, ASCII·숫자 범위, Decimal 정밀도를 검토해 수정 없이 수용했다. 이어 통합 smoke 2개와 최종 diff·범위 검사를 수행했다. 외부 채점에서 기존 14개 검사가 정상 종료로 모두 통과했고 허용한 세 파일 외 변경은 없었다. 원본 실행에서 생긴 캐시는 담당 에이전트가 정리했다.

담당 에이전트와 작업자는 모두 `gpt-6.1-sol` / `medium`이며 별도 문맥으로 실행했다. 원본 두 UUID의 실행 기록과 최종 사용량을 보존했다. 참고 토큰 합계는 794,483이고 준비부터 채점까지 전체 시간은 212.535초였다. 담당 에이전트 실행 시간은 188.552초, 작업자 실행 시간은 85.878초이며 두 실행은 겹친다. 두 시간을 더해 전체 소요 시간으로 표현하지 않는다. 기존 18회 비교의 수치에 이 보충 실행을 합쳐 조건 간 우위를 계산하지 않는다.

별도 독립 검토는 PASS다. 원본 dispatch와 실제 코드 작성, 담당 에이전트의 소스 읽기·수용·통합 검사, 외부 채점과 보호 파일 보존을 확인했다. 원본 assignment의 암호화된 본문은 독립 복호화하지 않았으며, 실제 접근·변경·검증 기록을 근거로 판단했다.

확인한 결론은 “명시적으로 요청된 단일 작업자의 구현 인계와 담당 에이전트 통합을 수행했다”까지다. 자발적 위임 판단, 복수 작업자 조정, 비용·속도 우위는 입증하지 않는다. 대표 6개 항목의 실행·채점·독립 검토와 개선본 적용은 마쳤지만, 전반적 우수성을 요구한 전체 목표는 아직 완료로 판정하지 않는다.
