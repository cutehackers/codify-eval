# 평가 실행 보완과 원본 보존

> 보존 상태: 2026-10-14 사용자 요청으로 원본 실행 로그·임시 실행 코드·보존 압축본을 삭제했다. 이 문서의 과거 경로·해시는 당시 기록이며, 현재 보존 자료는 README와 최종 보존 기록을 기준으로 확인한다.

이 문서는 고정된 `spec.md`를 바꾸지 않고 이후 실행 보완과 관측 한계를 설명한다. 비교 대상은 주 평가108건, 보조36건, Flutter 앱 작성18건, 보류24건이다. 예비4건과 교체 전 과거 실행은 비교186건에 더하지 않는다. 모든 평가 대상·진행자·독립 리뷰어는 `gpt-6.1-sol`, `medium`을 사용한다.

## 현재 앱 평가 방식

W01은 최소 scaffold에서 신규 앱을 작성하고, W02는 기존 앱에 기능을 통합한다. 실제 Linux release 실행 파일의 UI 흐름·디스크 저장·프로세스 종료 후 복원을 검사한다. 모델 자신의 의존성 준비·분석·build·실제 앱 검증도 별도로 판단한다. 외부 검사 성공이 모델 자신의 검증 수행을 대신하지 않는다. Linux 증거로 모바일 기기나 운영 환경 검증을 주장하지 않는다.

실행 조건과 순서는 `results/frozen-software-cohort-launch-v3.6.3.json`이 소유한다. 요청·사례·스킬·이미지·시간 제한·행동 판정 기준은 유지했다. 같은 입력 처리 보완을 W01/W02의 A/B/C0 각3회, 전체18건에 적용한다. 고정된 전체 범위와 순서는 과거 앱 성능 채점 전에 선택했으며 과거 성공 여부로 교체 대상을 고르지 않았다.

| 단계 | 사용 도구 | 필수 증거 |
|---|---|---|
| 새 실행 준비 | `tools/prepare.py`, `tools/dispatch.py` | 고정 요청·사례·스킬·이미지와 새 컨테이너·새 문맥 |
| 실제 종료 후 수집 | `tools/collect_schema_v364.py` | 실제 모델·완료·명령·소유 세션 결과 조회와 원본 hash |
| W02 고정 답변 전달 | `tools/dialogue_control.py` | 준비된 selector 직접 사용, 읽기 전용 파일, 같은 세션의 실제 수신 |

수집은 같은 종료 응답을 반복 수집하지 않는다. W02의 다음 입력은 `run.json`의 `dialogue_protocol.selector`를 그대로 `stage`에 전달해 공개한다. 새 앱 채점은 GUI 보완 entrypoint를 사용하며, 이 도구가 원래 고정 채점기와 고정 답변 검증을 호출한다. 보고 검토 직전 grade의 hash는 최종화 후 `grade-before-report.json`과 대조한다.

## 보존한 사건과 보완 범위

**기록1 — S03 입력 전달:** 과거6건 중5건은 유효 결과였고1건은 평가자 전달 오류였다. 암호화된 native 본문만으로 정확한 입력 문장을 증명하지 못한다. 원본171개 파일과 native를 보존하고 B/C0 각3회 전체6건을 새 고정 파일 방식으로 한 번 실행했다. 새6건의 실제 파일 수신·행동·독립 보고 결과는 모두 통과했다. 과거5건은 현재 비교의 S03 점수에 합치지 않는다.

**기록2 — native 수신 표현:** 첫 새 S03은 native의 `content.encrypted_content` 표현을 기존 검증기가 읽지 못했다. 원본을 바꾸거나 복호화하지 않고 메모리 복사본의 표현만 맞추는 보완을 고정했다. 원래 오류와 원본을 보존한 뒤 같은 산출물을 한 번 재판정했으며 모델을 다시 실행하지 않았다. 실제 파일 읽기와 수신자·토큰·부모 호출 연결은 여전히 필수다.

**기록3 — 소유 세션 조회 분류:** 원래 W01의 명령 문자열에 포함된 문자 `\${`를 수집기가 실행될 보간으로 취급해 정상 결과 조회6개를 도구 경계 위반으로 분류했다. 독립 승인 후 문자열 분류용 메모리 표현만 보완했다. 원래 소유 조회8개에6개를 더한14개가 확인됐으며, native·요청·응답·파일·명령·모델 실행은 바뀌지 않았다. 기존 분류와 원본은 별도 경로에 보존했다.

**기록4 — W02 selector 호출:** 진행자가 준비된 `reply` 대신 `choice` selector를 전달했다. 고정 stage가 입력 공개 전에 거부했고 두 번째 안내도 전달되지 않았다. 기존 W02를 재개하거나 오류를 제거하지 않았다. 기존 W01의 실제 결과도 성패와 관계없이 보존하고, 원래 비교 시작 순서를 유지하기 위해 전체18건을 새 문맥에서 실행하는 규칙을 성능 채점 전에 등록했다. 이 범위는 W01의 환경 장애 재시도라고 해석하지 않는다.

**기록5 — GUI 입력 제약:** 원래 W01은 모델 자신의 실제 앱 검증을 수행했지만 외부 검사기는 제목 입력 전에 포커스 요청 성공을 강제했다. 공개 요구는 이름 있는 편집 가능한 입력이며 이 포커스 반환값은 요구하지 않는다. 독립 검토 후 포커스는 최선 노력으로 처리하고 실제 `EditableText.set_text_contents` 성공은 필수로 유지했다. 다른 GUI 처리·이름·시간 제한·oracle 요구사항은 같다.

GUI 보완의 모의 검사39개와 독립 추가 검사24개가 통과했다. 실제 기준 구현2개는 통과했고, baseline2개와 의미적 실패 대조군4개는 의도한 요구사항에서 실패했다. 검증 도중 등록·audit helper를 보완해 최초 source hash 요약이 실패한 기록은 유지했다. 실행 당시 helper 복사본·최종 helper·변하지 않은 실제 GUI 코드·fixture·기존 채점기를 별도 대조했다. 이 대조 때문에 실제 앱 검사를 반복하지 않았다.

## 과거 앱 결과의 해석

기존 W01의 원래 최종 grade는 `fail`이며 behavior/report는 false, verification은 true다. GUI-only 진단을 한 번 사전 등록하고 동일한 보존 실행 파일을 읽기 전용으로 연결했더니 새 입력 방식에서 공개 요구13개가 통과했다. 실행 파일과 원래 fail grade의 hash는 같다. 진단은 현재 비교 점수에 넣거나 원래 fail을 지우는 데 사용하지 않는다. 당시 포커스 반환값·예외가 기록되지 않아 정확한 실패 분기는 미확정이며, 원래 fail만으로 모델의 구현 불능을 주장하지 않는다.

기존 W02는 `evaluation_error/evaluator_staging_fault`이고 성능 점수가 없다. 두 과거 실행의 runtime/results·독립 보고·native·외부 검사 작업 폴더는 `revisions/software-cohort-v3.6.0`에 보존했다. 최초265개 항목 목록에서 외부 검사 작업 폴더가 빠진 것을 발견해116개 항목을 별도 보존했다. 두 목록381개 항목을 함께 독립 검증했고 최초 목록과 고정 descriptor는 바꾸지 않았다. 과거 컨테이너는 같은 ID로 이름만 바꾸고 중지했다. 새 경로에 연결된 과거 컨테이너를 다시 실행하지 않는다.

## 최종 보고에 포함할 제한

교체 전 결과·평가자 오류·수집 보완·GUI 진단·추가 시간과 토큰을 현재 비교 결과와 구분한다. 비교의 실패를 통과할 때까지 반복하지 않는다. 판단 불가능한 실행을 성공률의 실패나 성공으로 임의 변환하지 않는다. 질문을 아직 관측하지 않은 실행을 질문0으로 계산하지 않는다.

S01 B 반복2의 자동 `unaffected_reason` 실패는 유지한다. 실제 문서와 독립 리뷰는 변경되지 않은 자식의 상태 보존 이유를 확인했으므로 자동 문구 분류와 의미 판단의 불일치를 별도 보고한다. 이 한 건으로 Codify 후보의 우위를 주장하지 않는다.

보류24건은 앱18건을 확정하고 후보를 고정한 뒤 마지막에 평가한다. 보류 결과로 스킬을 수정하면 새 보류 사례가 필요하다. 반복3회의 작은 차이와 과거·새 전달 방식의 비용 차이를 스킬 효과나 통계적 확신으로 해석하지 않는다.

수집 표현 보완 v3.6.4는 같은 실행 산출물만 정정했다. 기존 144건의 판정은 유지됐고, 새 앱 2건에서 확인한 소유 세션의 빈 입력 조회 17건만 경계 위반 목록에서 해제했다. 원본·오류 판정·제어 입력과 audit는 별도 보존했다. 새 버전은 230개 검사와 독립 검토를 거쳐 고정됐으며, 명령 끝의 공백·TAB·LF와 정확히 같은 apostrophe 치환만 허용한다. 모델 재실행, 성능 기준 변경, 스킬 변경은 없다.

실제 actor 경계 위반은 분류 보완 대상이 아니다. W01-C0-3의 send_message 호출2개는 원본에 남아 있고 frozen grader는 evaluation_error로 처리했다. 모델을 재실행하지 않는다. 이 실행은 유효한 앱 성능 판정과 질문 관측에서 제외되므로 미관측 항목을0으로 채우거나 코딩 실패·스킬 효과로 해석하지 않는다. 전체 실행 범위와 유효 비교 범위를 별도로 보고한다.


W02 공개 계약과 비공개 경로 목록의 불일치도 별도로 정정했다. IMPLEMENTATION.md를 추가한 두 실행은 공개 요청에서 허용한 문서 작업을 했으므로 actor 위반으로 해석하지 않는다. 기존 두 실패와 한 성공, 원본1596개 파일·링크,6개 actor/reviewer native를 `results/software-W02-original-scope-preservation-v3.6.5.json`의 위치·hash 목록으로 보존했다. 같은 산출물을 통과로 바꾸지 않고 문서 경로만 명시한 W02v365의9개 새 컨텍스트를 전체 조건에 적용한다. `results/frozen-software-W02-scope-v3.6.5.json`과 선택 일정은 고정됐지만 현재 추가 수집 오류를 해결하기 전 실행은 보류한다.

W01-A2는 String.raw 및 저장한 명령 접두사를 사용하는 원본에서32개 조회가 미인식됐다. `results/software-raw-template-original-preservation-v3.6.6.json`은 첫 수집과 평가 오류, 실제 native의 보존을 기록한다. 아직 오류를 해소하거나 앱 성능을 판정하지 않았다. 이 표현을 확인하는 작업은 실제 메시지 도구 위반인 W01-C0-3를 면제하지 않는다.

완료된 평가자 qualification 캐시51곳은 byte·hash·mode·symlink1326개 항목을 확인한 압축 파일로 복원할 수 있다. 최초 검증 중단143은 캐시 제거 전 발생했고 성공으로 기록하지 않았다. 이후 완료 증거는 `results/software-validation-cache-compaction-complete-v3.6.5.json`에 있다. 원본 앱 코드·실행 파일·native·성능 판정은 유지했다.

**기록6 — W01-A2 수집 복구 완료:** 위의 미해결 상태 이후 v3.6.6 수집 보완311개와 독립 추가 검사17개가 통과했다. 원본과 첫 오류를 보존하고 동일 산출물을 한 번 재수집했다. 요청·응답·앱 파일·명령·모델·시간·usage는 유지됐다. 실제 소유 조회21개를 확인했으며 외부 앱 검사와 새 문맥 보고 검토를 거쳐 최종 pass로 확정했다. W01-C0-3의 실제 메시지 도구 위반은 여전히 평가 오류로 제외한다.

**기록7 — W02v365-B1 요청 기록 복구:** 진행자가 두 번째 수집에 원래 답변 대신 파일 읽기 안내를 넣었다. 실제 답변255byte, 고정 selector, 읽기 전용 파일, 같은 세션 전달과 성공한 파일 읽기는 독립 검토로 확인했다. 원래 오류·audit·전체 native를 보존하고 `run.json`과 `turns.json`의 두 번째 request만 수정했다. 나머지 필드와 원본은 그대로다. v3.6.7 등록은 동일 산출물의 외부 채점 한 번만 허용하며 모델 실행·재수집·입력·행동 기준 변경은 허용하지 않는다. 이후 수집은 원래 답변과 파일 hash를 대조한 뒤 진행한다.
