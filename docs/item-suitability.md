# 평가 항목의 목적 적합성 점검

> 보존 상태: 2026-10-14 사용자 요청으로 원본 실행 로그·임시 실행 코드·보존 압축본을 삭제했다. 이 문서의 과거 경로·해시는 당시 기록이며, 현재 보존 자료는 README와 최종 보존 기록을 기준으로 확인한다.

작성일: 2026-10-10. 목적은 Codify가 Flutter 소프트웨어를 작성하고 검증하는 데 도움이 되는지 판단하는 것이다. 공개 스펙, E01~E12 요청, fixture 설명과 현재 스킬을 검토했고 독립 읽기 전용 리뷰를 함께 반영했다. 보류 사례의 정답은 검토하지 않았다.

판정: 기존 항목은 제한된 수정·기능 추가 평가에는 적합하지만 전체 앱 작성 평가로는 불충분하다. 실행 횟수를 늘려도 빠진 개발 역량을 측정할 수 없다. 소프트웨어 작성 성과를 판단하려면 W01 신규 앱과 W02 기존 앱 통합 결과를 필수로 함께 봐야 한다.

## 보완 항목의 합격 조건

**기준1: 실제 산출물.** 고정한 플랫폼에서 빌드되고 앱이 실행되어야 한다. 분석·테스트 성공만으로 실행 앱 완성을 인정하지 않는다. Linux desktop 결과로 Android/iOS 검증을 주장하지 않는다.

**기준2: 사용자 흐름.** 요청한 정상 흐름과 공개된 실패 흐름을 처음부터 끝까지 검사한다. W01은 생성·조회·수정·삭제와 실제 저장, W02는 기존 구조에 새 기능을 연결하고 관련 회귀를 확인한다.

**기준3: 요구사항별 증거.** 생성 코드 자체를 기대 결과로 삼지 않는다. 실제 프로세스 재시작, 실패·재시도, 기존 테스트와 보호 파일 보존을 독립 검사한다. 내부 구조가 기준 구현과 달라도 공개 동작을 만족하면 인정한다.

**기준4: 결과 분리.** 코드 동작·범위 보존·중대한 위반·완료 보고를 따로 판정한다. 필수 항목 하나가 실패하면 전체 합격이 아니다. 문서 길이·테스트 수·역할 수는 가점이 아니다. 효율은 성공한 실행끼리 비교한다.

## 평가 목적에 따른 결과 해석

| 코드 | 평가 질문 | 사용할 결과 | 해석 제한 |
|---|---|---|---|
| 판단1 | 요구한 프로그램이 실제로 동작하는가? | E01~E12의 동작 검사, W01/W02의 실제 release 실행 앱 | unit/widget 성공으로 실행 앱 전체 완성을 선언하지 않음 |
| 판단2 | 새 앱을 만들고 기존 앱에 안전하게 통합하는가? | W01의 자유로운 내부 구조와 신규 작성, W02의 기존 모듈·테스트·데이터 보존 | 최소 scaffold가 제공되고 의존성은 오프라인 캐시로 제한됨. 임의 SDK 선정·온라인 패키지 탐색·대규모 프로젝트 역량과 장기 유지보수 품질은 측정하지 않음 |
| 판단3 | 중요한 결정을 확인하고 정확하게 완료를 보고하는가? | E10/W02의 실제 질문·답변 시점, S01~S06와 모든 실행의 보고 검토 | 절차 점수가 코드 실패를 상쇄하지 않음. W02도 미결정 정책의 존재는 공개되어 있어 완전히 숨은 모호성을 스스로 찾는 능력까지 증명하지 않음 |
| 판단4 | Codify가 작성 성과를 개선하는가? | 같은 사례의 A(스킬 없음), B(수정 전), C(수정 후) 비교 | 고정 모델·동일 조건에서 관측한 차이를 보고함. 각 조건 3회로 작은 차이나 다른 프레임워크의 효과를 단정하지 않음 |

주 결과는 구현 동작, 기존 기능·파일 보존, 중대한 위반, 완료 보고를 각각 제시한다. 효율은 합격한 실행끼리 비교한다. E/S/W/H를 단일 성공률로 합치면 서로 다른 능력이 섞이므로 분리해서 보고한다. 보류 H는 개선 후 마지막에 사용한다. W02의 실제 저장 실패·재시도 증거는 생성 동작에서 확보한다. 완료 전환·보관·복원 각각의 저장 장애까지 검증했다고 보고하지 않는다.

## 현재 준비 증거

기존 frozen 사례는 변경하지 않았다. E05의 기존 API 기반 시작 행동 검사는 요구 동작 실패를 확인했다. 전체 oracle의 시작 코드 컴파일 실패는 별도로 기록했다. 컨테이너 기준 구현 16개는 테스트·분석을 통과했고 행동을 깨뜨린 16개 대조 구현은 모두 실패했다.

W01/W02의 공개 요구사항·시작 프로젝트·독립 실행 앱 검사·기준 구현을 추가했다. W01은 실제 파일 저장과 새 프로세스 복원, 공백·여러 줄·빈 내용, 생성·수정·삭제·취소를 검사한다. W02는 기존 데이터 호환과 필터·보관·복원, 실제 파일 장애 후 원래 동작 재시도를 검사한다. 채점기가 특정 저장 후 화면이나 비활성 버튼의 레이아웃을 강제했던 문제도 수정했다.

W02 v2의 기준 구현은 실제 Linux release 앱에서 13개 동작 검사를 통과했고 보관 동작을 제거한 대조 구현은 실패했다. W01 v2의 기준 구현도 실제 실행 앱에서 13개 동작 검사를 통과했고 복원·수정·삭제를 각각 깨뜨린 세 대조 구현은 모두 실패했다. 최종 공용 실행 도구로 W02를 다시 검사해 같은 통과·실패 결과를 확인했다. 최종 독립 검토에서 발견8·발견9를 찾아 W01을 수정·재검증했다. 정상 중복 노드 UI는 통과하고 본문 추가 변형은 분석·빌드 성공 후 정확한 값 검사에서 실패했다. 독립 재검토 결과는 software-suitability-final-review-v2.json의 pass다. 이 증거는 평가 사례가 정상 구현과 잘못된 구현을 구별하는지 확인한 것으로, 평가 모델의 작성 성과가 아니다. 최종 검증·독립 리뷰·공용 실행 도구 hash를 확인하고 frozen-core-v2.5.json에 W 사례를 고정했다. W 모델 평가는 주·보조 평가 다음에 실행하고 보류는 마지막이다. 기존 172회 계획에 W 18회를 더한 목표는 190회다. 예비 평가가 본 비교의 성공률에 포함되지 않는 원칙은 유지한다.
