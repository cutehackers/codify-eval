# 출력 한도와 코드 품질을 분리하는 평가 변경

> 보존 상태: 2026-10-14 사용자 요청으로 원본 실행 로그·임시 실행 코드·보존 압축본을 삭제했다. 이 문서의 과거 경로·해시는 당시 기록이며, 현재 보존 자료는 README와 최종 보존 기록을 기준으로 확인한다.

근거: 2026-10-13 사용자가 출력 한도 위반에는 유연하게 대처하고 결과의 품질을 먼저 평가하도록 지시했다. 모델은 계속 `gpt-6.1-sol`, reasoning은 `medium`으로 고정한다.

## 결정1. 출력 한도는 운영 지표로 기록한다

`max_output_tokens` 설정 초과만으로 완성된 코드의 기능 평가를 중단하지 않는다. 요청한 한도, 실제 출력, 잘림 여부, 재조회 횟수, 추가 토큰과 시간을 기록한다. 필요한 증거가 남아 있고 권한과 실행 범위가 검증되면 품질 채점을 진행한다. 잘린 출력 때문에 확인할 수 없는 항목만 미확정으로 남긴다.

앞으로 실행기는 지원 범위 내에서 출력량을 제한하거나 긴 출력을 파일로 보존하고 필요한 부분을 읽게 한다. 출력량 설정을 보안 권한과 동일하게 취급하지 않는다. 권한, 비밀 노출, 무단 파일 변경, 증거 변조 검사는 유지한다.

## 결정2. 기존 결과에는 별도 품질 채점을 추가한다

기존 비교의 입력, 코드, 테스트, 원본 로그, 실패 판정과 비용은 수정하지 않는다. O01/C17과 O02/C17은 원래 실행이 끝난 코드 스냅샷을 대상으로, 기존 공개·비공개 테스트와 분석기를 그대로 사용해 추가 채점한다. 모델을 다시 실행하거나 코드를 수정하지 않는다.

추가 보고에는 원래 운영 오류, 별도 기능 판정, 분석 결과, 범위·보안 확인 결과, 채점기 비용·시간·정리를 각각 담는다. 새 채점 시간은 원래 모델 실행 시간과 구분한다. 원래 비교의 전체 소요 시간도 그대로 보존한다. C0의 잘못된 capability 등 다른 오류를 출력 한도 오류로 재분류하지 않는다.

## 결정3. 품질을 우선해 개선 후보를 판단한다

요구사항 충족, 비공개 기능 검사, 실패 시 데이터 보존, 실제 결함 발견과 수정 확인을 먼저 본다. 이어 질문의 필요성과 정확성, 보안, 작업 분담의 효과, 토큰과 시간을 비교한다. 출력 한도 오류 수를 코드 품질 실패 수에 합산하지 않는다.

이번 추가 채점은 사용자 지시에 따른 사후 보완 평가다. 기존 동결 비교의 성공 판정을 덮어쓰거나, 추가 채점만으로 최종 우수성이 입증됐다고 주장하지 않는다. 다음 비교부터 이 분리 기준을 모든 조건에 동일하게 적용해 동결한다.

## 완료 조건

원본 코드·테스트 해시 일치, 독립 검토, 실제 채점 결과와 정리 증거가 있어야 추가 평가 완료로 기록한다. 정상 종료한 모델의 원래 결과물만 사용한다. 증거가 부족하면 해당 항목의 부족 이유를 명시한다.
