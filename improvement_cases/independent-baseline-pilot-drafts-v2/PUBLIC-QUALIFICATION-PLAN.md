# Independent baseline difficulty pilot draft qualification
These B01-B04 clusters are a v2 repair of independently authored drafts and remain drafts for baseline difficulty exploration, not final confirmation. No SDK, analyzer, Dart tests, container, model, native allocation or pilot has been executed. Drafts do not establish difficulty, ceiling effects, quality gain, cost gain, wall-clock gain, sample size or a noninferiority margin.

Each public/ directory is a separate package intended to become a fresh isolated Git repository at runner admission. No generated .git history or shared application source is included. Only editable paths in metadata may change. Every cluster has at least three authored source files and an independent presentation module, with dependent business modules integrated by the evaluated root. Optional orchestration has no benefit score based solely on agent count. Runtime ownership, cost collection and integrations belong to the root owner.

Qualification1. Materialize a clean public workspace per cluster and branch, resolve a single admitted Dart SDK and dependency lock, run analyzer and public tests against the untouched starter. Preserve stdout, stderr, exit codes, exact commands and runtime hashes. Verify public tests pass and only editable source paths are exposed. The author has not resolved dependencies or created a lock.
Qualification2. Run private behavior acceptance out of band against each untouched starter. A necessary-question starter is not expected to satisfy the selected branch. Record genuine expected unmet behavior, not incidental dependency or compilation failure. If any starter acceptance passes unexpectedly or fails to compile, repair the draft before admission.
Qualification3. In a separate clean public workspace, overlay private reference/lib files; preserve public models, dependencies and tests. For question clusters also overlay the assigned reference/branches/<id>/lib/decision.dart and pass that branch's OWNER_BRANCH define to acceptance tests. Run analyzer, public and full private tests for all reference branches. A null decision in the common question reference is deliberately incomplete until an owner branch overlay is selected. No reference is qualified before all branch executions pass.
Qualification4. Apply every private/mutants JSON replacement once to a passing branch reference. Verify source match count is exactly one, run its must_fail tests, require behavior-test failure rather than parse/analyzer failure, and preserve mutant evidence. Respect optional branches field; all applicable branches must be checked. These are specific behavior-removal or violation mutants, not randomly generated mutations. A surviving mutant requires stronger relevant oracle evidence or a corrected mutation, with reasons preserved.
Qualification5. An independent reviewer checks each public requirement versus private/public-to-private-map.json, oracle assertions, branch facts and reference. No assertion may demand an unpublished fixed product choice. Owner-reply branches are private and are part of the eventual audited protocol. Review needed for meaningful decision coverage, recovery paths, compatibility, scopes, security isolation and absence of leaked answer/implementation in public materials.
Qualification6. Admit a live-question adapter before any product model run. Fully specified clusters need a no-question admission path and transcript capture. Necessary-question clusters need semantic question admission, recorded preassigned allowed owner branch, reply delivery, unrelated/duplicate-question handling, no default-answer leak, and same-branch oracle execution. No scripted intended-question string may substitute for judgment. Demonstrate adapter branches and behavior with controlled adapter tests before models. The adapter and runner are not authored here.

There are six requirement kinds per cluster, 24 cluster-level qualification checkpoints total. Branch-dependent executions expand these checkpoints and must not be reported as independent product samples. B01/B02 each have one reference mode. B03/B04 each have two owner reply branches. Neither model superiority nor expected baseline failure is assumed.

After qualification, the evaluation owner may freeze candidate, public/private cases, grader, adapter, dependencies and runtime hashes for a separate exploratory baseline pilot. Decide admission, runtime budget and analysis before allocating models. Root remains blind to private task bodies, reference bodies and owner answers until the candidate is fixed. Pilot-informed candidate changes consume these cases as development material and require separate final confirmation cases. Do not silently reclassify these drafts as sealed, qualified or held out.

V2 repair admission. Every qualification checkpoint remains false until independently requalified against this cohort. B01/B02 are byte-identical provenance only and do not inherit qualification. B03/B04 require an additional null-decision negative reference mode without any owner reply overlay. The private fixture contract specifies its define and mode. Run dedicated unresolved-decision mutants only in that negative mode, and ordinary branch mutants in each applicable assigned branch. Never treat that negative mode as an allowed owner reply. Private branch identifiers select oracle behavior and do not impose an undocumented implementation representation. New input-contract boundary tests and mutants require behavior-failure evidence.
