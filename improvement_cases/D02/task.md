# D02: Authorized local document persistence

Repair DocumentRepository and LocalDocumentFiles. This is a local draft store shared by several account owners. Callers provide an AccessPolicy, never assume the caller owns the requested document. Keep the public exports from lib/main.dart. No GUI is required.

Public contract:
1. Preserve DocumentRepository(DocumentFiles, AccessPolicy), Future<void> save(String owner,String id,String body), Future<String?> load(String owner,String id), LocalDocumentFiles(Directory root, {DocumentFileOperations? operations}), DocumentFiles.read/write and AccessPolicy.canRead/canWrite. Root is an existing trusted directory on Linux/macOS. Hostile concurrent filesystem manipulation and cross-process ordering are outside scope.
2. Both owner and id must match `^[a-z][a-z0-9_-]{0,31}$`. Invalid input throws ArgumentError before policy calls or file I/O. No trimming or normalization. The storage key is exactly `<owner>.<id>.json`. The file adapter independently rejects any other key with ArgumentError before I/O.
3. Check canWrite(owner) on every valid save invocation and canRead(owner) on every valid load invocation, before enqueuing file work. These permissions are independent. Denied calls throw AccessDenied, whose toString() is exactly `Access denied`, and perform no file work. Do not cache authorization or document content. A permitted invocation keeps its permission decision while queued.
4. Save exactly a JSON object with four fields: integer version 1, owner, id, and string body. Preserve arbitrary Unicode, whitespace, quotes, null characters and empty bodies. Return from save only after successful persistence. Load returns null only when the key is absent. Decode existing files fresh on each load, require exactly those four fields and matching owner/id/version/body type. Malformed, wrong-owner, wrong-id, unknown-version, wrong-type or extra-field records throw StorageFailure.
5. All authorized operations through one repository execute in invocation order, including loads following saves. A failed operation must not prevent later operations. Concurrent saves to one key must leave the last invocation's successful body persisted. Different owners with the same id remain isolated.
6. LocalDocumentFiles reads UTF-8 and writes via a temporary file in the same root followed by rename. Await write/flush and rename before completing. Preserve existing destination contents if writing the temporary file fails. Remove temporary files after success or failure where cleanup is possible. Missing root on write is a failure. Reject a destination that is a symbolic link or any non-file entity before reading/writing. Never follow or overwrite a leaf symlink. Root creation is not required.
7. File I/O errors and decoding/schema errors become StorageFailure, whose toString() is exactly `Storage operation failed`. Never retain or expose original exception messages, paths, tokens or file contents through returned exception text. LocalDocumentFiles itself must redact I/O errors. Identifier errors remain ArgumentError and denied access remains AccessDenied.

Only lib/** and test/** may change. Keep pubspec and public API names. Verify using `flutter pub get --offline` and `flutter test`. Public smoke tests are examples, not the complete contract. Additional evaluation tests exercise all requirements above.

The existing `test/smoke_test.dart` is protected. You may add tests but must not edit or remove this smoke test.

Public deterministic file-I/O interface:
- Keep the exported DocumentFileOperations and SystemDocumentFileOperations from file_operations.dart. Omitting the optional operations constructor argument uses SystemDocumentFileOperations. Existing LocalDocumentFiles(root) callers must keep working.
- When operations is supplied, route all file type checks, existence checks, reads, writes, renames and deletes through that instance. Its signatures are type(String path, {required bool followLinks}), exists(File), read(File), write(File,String,{required bool flush}), rename(File,String destination), and delete(File). The system implementation delegates to dart:io and uses UTF-8.
- Request write(..., flush: true) for the temporary file. An operations.write error can occur after partial content is written or while flushing. In both cases preserve the existing destination, do not call rename, attempt temporary-file deletion, and return redacted StorageFailure. A rename error also requires temporary cleanup and redacted StorageFailure. Tests can use supplied operations to fail those public operations deterministically. Temporary filename spelling is not part of the contract.
- A denied operation completes with AccessDenied without waiting behind authorized queued work. This follows the requirement to reject before enqueuing file work.
