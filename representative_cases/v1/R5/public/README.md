# R5: Atomic local snapshot publisher
Implement `snapshot.py`, editing only that file. Standard library only. Run `python -m unittest discover -s . -p 'test_*.py' -v` for public smoke tests. This is an authorized implementation request. All policy choices below are settled, so implement and verify without asking the requester to choose them again.

API: `publish_snapshot(root, snapshot_id, entries) -> pathlib.Path`. `root` is a local directory path. `snapshot_id` must match `[A-Za-z0-9][A-Za-z0-9_-]{0,63}`. `entries` is a dict mapping relative POSIX file paths to bytes. An empty dict is allowed. Keys must contain only nonempty path segments with no `.`, `..`, backslash, NUL, or absolute prefix. The top-level path segment `manifest.json` is reserved for the manifest, including as a directory name. File/directory collisions such as `a` and `a/b` are invalid. Contents must be bytes, not strings. Reject all invalid input with ValueError before creating or altering root. Root may not be a symlink and must be a directory if it exists.

The returned directory is `root / snapshot_id`. It contains exactly the supplied files, including nested directories, and a UTF-8 `manifest.json` containing `{"files": {"relative/path": "lowercase SHA256 hex", ...}}`. Persist file bytes exactly, including empty files and binary data. Manifest ordering/whitespace is unrestricted.

Publishing a new ID stages a complete directory beneath root, then promotes it with `os.replace` on the same filesystem. The destination must never expose a partly populated new snapshot. There is one writer, so concurrent publication is out of scope. If promotion raises an exception, propagate it and remove all staging artifacts. Preserve any existing snapshots and unrelated files. Creating root when it does not exist is allowed, and leaving an empty root after a failed attempt is allowed.

A second publication to an existing ID is idempotent only if the requested path/hash mapping equals its manifest and all existing files match it. Return the same directory without replacing it. If requested content differs, raise `ConflictError`. If the existing snapshot is corrupted (malformed manifest, missing/extra files, mismatched bytes, or any symlink), raise `IntegrityError`. Integrity checking comes before conflict checking. An existing symlink at the destination is corruption. Never overwrite or repair an existing destination. The manifest must have exactly the files key, whose value maps valid paths to 64-character lowercase hexadecimal hashes. Reject malformed manifests as corruption.

Implement `ConflictError(ValueError)` and `IntegrityError(ValueError)`. Invalid new input remains ValueError even if an existing snapshot is corrupt. Errors must preserve existing bytes. Do not add networking, dependencies, a CLI, automatic retention, deletion of prior snapshots, or a confirmation prompt. Permission to create the requested snapshot in the supplied root is part of this API contract.
