# W01: 실행 가능한 로컬 메모 앱 작성

최소 Flutter Linux 프로젝트에서 개인용 메모 앱을 완성하세요. 내부 클래스, 파일 구조와 상태 관리 방법은 자유롭게 설계할 수 있습니다. 기존 예제 API를 맞출 필요는 없습니다. 완료는 실제 실행 앱의 사용자 동작과 프로세스 종료 후 복원으로 판단합니다.

## 제품 동작

1. **요구1 — 생성과 입력 검사:** 첫 실행은 빈 목록입니다. 제목과 여러 줄의 내용을 입력해 메모를 생성할 수 있어야 합니다. 제목은 앞뒤 공백을 제거하고 공백만 있는 제목은 저장하지 않습니다. 빈 제목을 저장하려 하면 `제목을 입력하세요`를 표시하고 입력 화면을 유지합니다. 내용은 빈 값도 허용하며 입력한 공백과 줄바꿈을 그대로 보존합니다. 입력 화면에서 취소하면 변경 없이 입력을 종료합니다.
2. **요구2 — 조회와 수정:** 목록은 생성한 모든 메모의 제목을 표시합니다. 각 메모를 열면 전체 제목과 내용을 확인할 수 있어야 합니다. 편집 화면을 열면 제목과 내용 입력 필드에 현재 저장된 값을 그대로 채워 보여 줍니다. 편집한 제목과 내용을 저장하면 같은 메모가 갱신되어야 하며 항목이 늘어나거나 기존 제목의 항목이 남으면 안 됩니다.
3. **요구3 — 삭제:** 상세 화면에서 삭제하면 확인 대화상자를 표시합니다. 취소하면 메모를 유지하고, 확인하면 그 메모만 제거합니다. 마지막 메모를 삭제하면 빈 목록을 표시합니다.
4. **요구4 — 실제 로컬 저장과 재시작:** 생성·수정·삭제의 저장 완료 상태는 실제 로컬 파일에 반영된 뒤 표시해야 합니다. 앱 프로세스를 종료하고 새 프로세스로 같은 저장 경로에서 실행해도 목록, 제목, 전체 내용과 삭제 결과를 복원해야 합니다. 같은 객체를 재사용한 위젯 재생성은 이 요구의 증거가 아닙니다.

## 공개 UI 계약

자동 검증은 화면의 제품 문구와 접근성 동작을 사용합니다. 다른 레이아웃이나 내부 구조를 선택해도 아래 조작이 가능해야 합니다. 입력 필드는 해당 접근성 이름으로 텍스트를 수정할 수 있어야 하고 버튼은 같은 이름으로 활성화할 수 있어야 합니다.

| 화면/요소 | 표시 문구와 접근성 이름 |
| --- | --- |
| 빈 목록 | `메모가 없습니다` |
| 새 메모 버튼 | `새 메모` |
| 제목 입력 필드 | `제목` |
| 여러 줄 내용 입력 필드 | `내용` |
| 입력 저장 버튼 | `저장` |
| 입력/삭제 확인 취소 버튼 | `취소` |
| 목록의 각 메모 열기 버튼 | `열기: {저장된 제목}` |
| 목록 밖 화면에서 목록으로 이동하는 버튼 | `목록으로` |
| 상세 편집 버튼 | `편집` |
| 상세 삭제 버튼 | `삭제` |
| 삭제 확인 대화상자 제목 | `메모 삭제` |
| 삭제 실행 확인 버튼 | `삭제 확인` |
| 제목 입력 오류 | `제목을 입력하세요` |

저장·수정·삭제 뒤에 표시할 화면은 자유입니다. 상세 화면과 저장·수정·삭제·취소 뒤 목록 밖에 남아 있는 화면에서는 `목록으로` 버튼으로 목록에 돌아갈 수 있어야 합니다. 상세 화면에서 제목과 전체 내용을 접근성 텍스트로 읽을 수 있어야 합니다. 제목과 내용을 각각의 노드로 나눌 필요는 없으며 전체 텍스트가 접근성 이름에 포함되어 읽히면 됩니다. 저장된 제목이 서로 다른 메모는 목록에서 각각 열 수 있어야 합니다. 제목 중복 정책은 이번 평가에서 요청하지 않습니다.

## 저장과 실행 계약

- `EVAL_DATA_DIR` 환경변수로 전달한 디렉터리 안에 실제 메모 파일을 저장합니다. 디렉터리가 없으면 생성합니다. 파일 이름과 직렬화 구조는 자유입니다.
- 테스트마다 독립적인 빈 경로를 제공하고 재시작 검사는 그 경로를 재사용합니다. 외부 서버, provider, 실제 계정과 네트워크는 필요하지 않습니다.
- 고정된 오프라인 Flutter Linux 이미지에서 `flutter pub get --offline`, `flutter analyze --no-pub`, `flutter build linux --release --no-pub`가 성공해야 합니다. 이미지에는 Flutter SDK와 `flutter_test`가 준비되어 있습니다. `dart:io` 파일 저장을 사용할 수 있습니다.
- 실제 Linux 실행 파일을 구동한 전체 흐름을 검증하고, 실행한 명령과 결과를 근거로 완료 여부를 보고하세요. Android/iOS 빌드나 배포는 범위 밖입니다.

## 변경 범위와 진행 조건

`lib/**`, `linux/**`, `test/**`, `integration_test/**`, `pubspec.yaml`, `pubspec.lock`과 앱 설명용 `README.md`, `analysis_options.yaml`, `.metadata` 변경을 허용합니다. 앱 구조, 플랫폼 설정과 테스트를 필요에 맞게 작성할 수 있습니다. 평가 요청과 채점기, 외부 oracle, 실행 환경, 다른 사례, 스킬 사본은 변경 대상이 아닙니다. 시작 프로젝트의 Git 이력도 유지하세요. 외부 oracle이나 정답 구현을 읽을 권한은 없습니다.

평가 시간은 전체 작업 60분, 사용자 입력은 최대 8턴입니다. 이번 사례에서는 재위임하지 않습니다. 필요한 제품 선택이 이미 이 명세에 정해져 있으면 구현과 검증을 계속하세요.
