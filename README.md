# Codify 평가와 개선

Codify는 명확한 요청이나 승인된 계약을 실제 코드 변경과 검증된 결과까지 연결하는 스킬이다. 특히 기존 저장소에서 입력·권한, 저장·복구, 비동기 처리처럼 실패 경로를 함께 다뤄야 하는 작업에 적합하다. 담당 에이전트가 범위·통합·완료를 책임지며, 필요한 결정만 질문하고 유용한 경우에 작업을 분담한다.

현재 개선본은 **C24**다. 대표 6개 과제를 A(스킬 없음)·C0(원본)·C24로 비교한 18회 실행에서 216개 비공개 검사가 모두 통과했다. 별도 R6 실행에서는 작업자 한 명의 구현 인계·담당 에이전트 통합과 14개 검사 통과를 확인했다. 사용자는 이 대표 결과로 마무리하도록 선택했다.

이는 전반적 우수성을 입증한 결과는 아니다. C0의 특정 비동기 종료 결함을 C24와 A가 피한 것은 확인했지만, 질문·보안·속도의 전반적 우위와 스킬 자체의 인과적 효과는 미입증이다.

## 사용 방법

현재 사용자 설치 위치는 `~/.agents/skills/codify/`다. 자동 호출은 꺼져 있으므로 요청에 `$codify`를 명시한다. 새 컴퓨터에서는 [C24 폴더](snapshots/C24/)의 `SKILL.md`, `references/`, `agents/`를 같은 위치에 함께 복사한다.

```text
$codify
목적: 주문 저장 실패 후 재시도가 중복 주문을 만들지 않도록 수정해줘.
시작 경로: 실제 저장소의 주문 API와 저장 모듈.
범위: 해당 모듈과 영향받는 테스트. 기존 사용자 변경을 보존해줘.
완료 조건: 정상 저장, 같은 요청 재시도, 저장 실패 후 상태 보존을 확인해줘.
결과: 바뀐 행동, 실제 검사 결과, 남은 한계를 보고해줘.
```

Codify는 모델을 정하는 스킬이 아니다. 모델과 reasoning은 실행 환경에서 설정한다. **이번 최종 평가와 보충 실행은 `gpt-6.1-sol` / `medium`으로 고정했다.**

## 적합한 사용 사례

아래는 스킬 지침에 근거한 사용 제안이다. 모든 언어·프레임워크에서 비교 우위를 입증했다는 뜻은 아니다.

| 사례 | 맡기기 좋은 작업 | 요청에 포함할 핵심 |
|---|---|---|
| 사용1 | 재현 가능한 버그 수정과 관련 회귀 검사 | 재현 조건, 기대 행동, 영향 범위 |
| 사용2 | 외부 입력·파일 경로·권한이 얽힌 기능 | 허용 입력, 권한 기준, 효과 발생 순서 |
| 사용3 | 저장·중복 요청·재시도·복구 기능 | 중복 기준, 실패 시 보존할 상태, 복구 조건 |
| 사용4 | 동시 요청·취소·늦은 응답 처리 | 호출·작업 소유권, 종료 후 기대 행동 |
| 사용5 | 결과를 바꾸는 정책이 빠진 기능 | 이미 결정한 내용, 미결정 선택, 독립적으로 진행할 작업 |
| 사용6 | 여러 모듈의 기능 통합과 유용한 분담 | 공개 인터페이스, 파일 소유권, 최종 통합 책임 |
| 사용7 | 승인된 계약을 따라 지속적으로 구현하는 작업 | 승인 상태, 현재 작업 범위, 완료 기준과 증거 |

### 복사해서 쓰는 샘플 프롬프트

`[시작 경로]`와 `[계약 경로]`는 실제 저장소 경로로 바꾼다. 아래 정책과 완료 조건도 해당 프로젝트에 맞게 조정한다.

**사용1 — 버그 수정**

```text
$codify [시작 경로]에서 빈 검색 결과를 선택하면 발생하는 예외를 수정해줘.
빈 목록에서는 이동하지 않고 단일·복수 결과의 기존 동작은 유지해줘.
재현 조건과 관련 회귀를 검증하고, 변경 내용과 실제 검사 결과를 보고해줘.
```

**사용2 — 입력·권한 검증**

```text
$codify [시작 경로]의 문서 내보내기에 기존 권한 정책과 경로 검증을 적용해줘.
권한 없는 요청은 저장 전에 거부하고, 출력 경로는 허용 디렉터리 안으로 제한해줘.
외부 렌더러의 결과도 저장 전에 검증하고 정상·거부·잘못된 출력 경로를 검사해줘.
```

**사용3 — 저장·재시도·복구**

```text
$codify [시작 경로]의 작업 큐가 재시작 후에도 미완료 작업을 복원하도록 구현해줘.
같은 사용자·요청 키의 재시도는 중복 작업을 만들지 않고, 저장 실패 시 기존 상태를 보존해줘.
실제 파일 또는 DB로 중복 요청·재시작·실패 후 재시도를 검증해줘.
```

**사용4 — 비동기 처리**

```text
$codify [시작 경로]에서 동일 키의 동시 조회가 진행 중인 작업 하나를 공유하게 해줘.
호출 하나의 취소는 다른 호출에 영향을 주지 않아야 하고, 종료는 작업 정리를 기다려야 해.
종료 중 대기 호출에는 취소를 전달하고 새 요청은 거부하도록 구현·검증해줘.
```

**사용5 — 미결정 정책 확인**

```text
$codify [시작 경로]에 재고 예약을 구현해줘. 같은 SKU는 합산하고 성공한 주문의 재시도는 중복 예약하지 않아야 해.
재고 부족 시 전체 거절과 부분 예약 중 어느 정책을 쓸지는 미정이니 구현 전에 물어봐줘.
이미 결정한 내용은 다시 묻지 말고, 답변 후 해당 정책을 구현·검증해줘.
```

**사용6 — 모듈 분담·통합**

```text
$codify [시작 경로]의 CSV 파서와 가져오기 처리·요약 기능을 완성해줘.
분담이 도움이 되면 파서와 처리·요약의 파일 소유권을 나누고 공개 인터페이스를 공유해줘.
작업자의 실제 코드를 검토·반영한 뒤 담당 에이전트가 최종 통합 동작과 회귀를 검증해줘.
```

**사용7 — 승인된 계약 구현**

```text
$codify [계약 경로]의 승인된 계약을 기준으로 [시작 경로]의 다음 미완료 작업을 구현해줘.
현재 작업의 완료 조건과 기존 변경을 보존하고, 결과를 바꾸는 새 결정만 질문해줘.
완료 보고에는 요구사항별 검사 결과와 실행하지 못한 필수 검사를 구분해줘.
```

자세한 상황 설명과 결과 확인 방법은 [사용 사례 문서](docs/codify-use-cases.md)에 있다. 작은 수정은 직접 구현·검증할 수 있으며, 파일이 여러 개라는 이유만으로 분담하거나 새 계약 문서를 만들 필요는 없다.

## 원본과 최종본

- [원본 C0](snapshots/C0/)와 [최종 C24](snapshots/C24/)를 보존했다.
- 스킬의 변경 파일은 `SKILL.md`, `references/delivery.md`, `references/orchestration.md` 세 개다.
- 변경 전후의 구체적인 비교와 실제 효과는 [과정 보고서](docs/evaluation-improvement-report.md#원본과-c24의-차이)에서 확인한다.
- C24는 C0 대비 참고 토큰이 13.8%, 모델·도구 실행 시간이 2.9% 적었다. 준비부터 채점까지 전체 시간은 4.8% 길었다. 토큰은 합격 기준이 아닌 참고 지표다.

## 저장소 구조와 보존 상태

| 경로 | 역할 |
|---|---|
| `docs/` | 사용 안내, 계획, 최종 결과와 과정 보고서 |
| `snapshots/` | 후보 버전과 설치 전 복원본 |
| `representative_cases/v1/` | 대표 6개 과제의 공개 계약·시작 코드와 비공개 검사·기준 구현 |
| `tools/` | 준비·채점·사용량 수집·리소스 정리 도구 |
| `inputs/` | 실행에 전달한 요청과 보충 시나리오 지시 |
| `results/` | 고정 입력 목록, 판정, 독립 검토, 승인·설치·정리 기록 |
| `fixtures/`, `contract_cases/`, `software_cases/`, `improvement_cases/` | 이전 평가와 개발용 사례. 최종 대표 결과와 구분해 해석 |

평가 후 생성 캐시와 소유 Docker 리소스를 정리했다. 이어 사용자 요청에 따라 원본 실행 로그, 임시 실행 코드, 채점된 실행 파일과 보존 압축본을 삭제했다. 소스·스킬 스냅샷·문서와 문서에서 참조하는 핵심 결과 JSON 30개는 보존했다. [최종 보존 기록](results/improvement-v1/repository-retention-outcome-v1.json)

최종 저장소는 스킬·코드·검사 사례·보고서·핵심 결과 요약을 관리한다. `runtime/`과 원본 로그·압축본은 삭제했으므로 과거 실행을 원본 기록으로 재감사할 수 없다. 결과 JSON의 원본 경로·해시는 당시 기록이며 파일의 현재 존재를 뜻하지 않는다. 후속 평가는 새 버전·실행 경로·고정 입력으로 수행한다.
