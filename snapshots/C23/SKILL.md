# Codify

Preserve scope, public contracts and unrelated work. Complete the original behavior with evidence for its applicable risks.

## Bound discovery and resolve decisions

Start at named entry points. Batch confirmed instructions, dirty status, relevant source/interfaces/callers/tests and, when possible, this entrypoint in one bounded read. Missing optional instructions must not stop required reads. Resolve unknown paths/tools once through an authorized fallback, then batch remaining known inputs. Number locations when needed. Reuse unchanged source via missing ranges or changed hunks. Expand for a concrete unresolved dependency or decision, and stop when the edit boundary and acceptance checks are understood. Distinguish enforced interface limits from adjustable output budgets. Capture needed evidence within authorized budgets, splitting for limits or gaps.

Ask one bundled question only when an unresolved choice affects public behavior, persistence, authorization, security, money, destructive effects, compatibility or acceptance. Preserve answers and existing authorization. Keep other assumptions narrow, reversible and visible.

For specification/slicing/approval/amendment, read [references/specification.md](references/specification.md). Proposed or review-pending durable slices remain ineligible despite parent approval. Preserve amendment resets and required independent review. Use [references/intent-interview.md](references/intent-interview.md) for unresolved intent and [references/delivery.md](references/delivery.md) for sustained slices or unresolved delivery/coverage questions. Read only relevant sections. Ordinary implementation/verification/reporting use this entrypoint without default delivery reads, added approval or documents.

## Map evidence to acceptance and risks

Before tests, map acceptance/risks to existing checks in compact working notes or an existing task record, not a new deliverable. Reuse adequate coverage. Check uncovered outcomes, boundaries and failures:

- Public behavior, shared contracts and callers: behavioral checks, affected regressions and required build/static checks.
- Trust boundaries: invalid or hostile inputs, denial before side effects, containment and safe error output as applicable. At external or injectable boundaries, validate successful outputs against public format, authorization and reporting guarantees before writes or final success. Returned metadata must agree with committed state. Follow defined failures without inventing error codes or validation order.
- Persistence: validation before writes, preservation and recovery after partial failure, and compatibility for changed formats.
- Async work: applicable ordering, concurrent ownership, late results, backpressure, cancellation and failure recovery.
- Repository policy: every command whose required trigger applies.

Choose cases by distinct behavior, validation branch, error precedence or state transition. Preserve explicitly required and adversarial cases. Preserve boundary values, hostile input classes and async interleavings with distinct plausible failure mechanisms, even with equal outcomes and no observed defect. Remove only repetition without a distinct requirement or mechanism. Do not cap tests numerically, skip applicable risks or equate count with coverage.

Negative cases must satisfy earlier preconditions to reach the intended branch, with expected errors from the public contract. Infrastructure repairs must preserve the invalid input and verify that branch. Failure for a different reason leaves its gap open. Establish focused Red when practical. Dependency, compilation or timeout failures alone are not Red. Reuse project harness/import conventions. Async tests must bound their full lifecycle, assert relevant immediate effects and settle or cancel started work even after assertion failure.

## Make one coherent change and verify

Confirm dependency readiness for this checkout/revision. Reuse valid installations via documented no-resolution options. Prepare missing dependencies once with documented commands and no unauthorized manifest/lockfile edits. Retain explicitly required setup/verification commands. After timeout, inspect readiness and documented environment/cache mode before resolving again.

Edit behavior and necessary tests coherently. Preserve untouched declarations through targeted edits/range formatting, restoring unrelated formatter changes. Inspect hunks against starting scope/contracts before focused and required affected checks. Preserve each exit status, stop dependent steps on failure and never hide failure with later success.

Before dispatch, use the supplied interface, literal-argument example and exact documented payload keys/types. Semantic report sections are not API fields: place findings, results and limitations in allowed fields. Resolve consequential missing interface details from authorized documentation or interface responses before dependent calls. Keep an inner shell command one argument. Check outer and inner expansion of source/assertions. Serialize for the receiving parser and shell-quote each argument, without another shell layer. JSON serialization is not shell quoting. Only confirmed pre-dispatch rejection proves non-execution. Otherwise inspect receipts and state before retrying, preserving interface restrictions and failed evidence.

Choose waits for expected runtime. Observe returned sessions through the same handle at meaningful intervals. Do independent useful owner work, then wait for completion instead of repeated short probes. A polling timeout does not authorize restart. Classify behavior, environment and evidence-collection failures before changing code.

Plan final required verification to also report changed files, whitespace and status, then remove only authorized task-generated files after successful checks. Preserve individual exit statuses and stop dependent steps on failure. Retain required evidence and settle async work before cleanup. Known cleanup paths/order need no separate cleanup-only call. Keep cleanup separate after verification failure or when it needs a new decision. After passing checks, reuse unchanged hunk inspection and matching results. Add evidence only for new edits, failures, policy requirements or concrete uncovered risks. New edits require inspection and affected verification.

## Preserve independent assurance and ownership

Delegate for consequential independent judgment or useful parallel work with independent dependencies and distinct file ownership. Preserve required reviews and independent challenge for material correctness, security, compatibility or persistence risks. Before optional reservation, identify the unresolved question, decision-changing evidence and concurrent owner work. Keep bounded, understood work with its owner when handoff adds waiting without needed results. A clean review does not prove it was unnecessary.

Before reservation, confirm that the worker can access its permitted inputs. Owner tool responses are not automatically shared. Supply actual relevant public rules and interacting guarantees, or a contract location with confirmed access for that role. Requirement labels or a request to read its task do not establish access to the owner request. Include current source revision, confirmed paths/tools, question and affected decision, read/write boundary and stopping condition. Limit the first numbered source read to needed code/contracts, then read ranges or changed hunks only for a named missing fact.

Ordinary bounded read-only review can use this entrypoint. For multiple workers or write ownership, read the relevant role/ownership sections of [references/orchestration.md](references/orchestration.md). Use its review questions and high-risk sequence for consequential closure. Keep one owner of scope, overlapping edits, diagnosis, integration and completion. Use or explicitly reject each contribution. Follow runtime model policy and count workers, failures, waits, review and integration in total cost/time.

Give reviewers the owner check map: revision, behavior, actual runner and result for completed checks, with planned checks unverified. Request concrete counterexamples to a risk/assurance question beyond the map. Run owner checks at the source state where their results apply, retaining required commands and final integrated verification. Reuse matching results unless independent execution is required, source changed, evidence is missing or a concrete counterexample warrants another check. Never attribute owner checks to a reviewer.

Missing worker rules or inputs leave coverage open. Repair the handoff through authorized delivery when allowed, retaining failed assignment and cost. Accept findings only within demonstrated scope. Incomplete coverage cannot fulfill required independent review, and worker evidence cannot replace final integrated verification.

Confirm every original acceptance criterion against current evidence. Report delivered behavior, actual checks, assumptions and gaps. Distinguish proposed, approved, implemented and runtime-verified work. Unexecuted required checks leave completion open.
