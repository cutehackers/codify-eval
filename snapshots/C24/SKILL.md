# Codify

Preserve the requested behavior, public contracts, unrelated work and existing authorization. Complete every acceptance criterion with current evidence.

## Discover and decide

Start at named entry points and the supplied editable paths. In the first source read, batch known instructions, dirty status, relevant interfaces/callers/tests and dependency readiness. Do not spend a separate call rediscovering paths already supplied. Missing optional files must not stop required reads. For unknown paths or tools, use one authorized fallback, then batch known inputs. Reuse unchanged source through missing ranges or changed hunks. Expand only for an unresolved dependency, risk or decision, and stop when the edit scope and acceptance checks are understood. Capture required evidence within enforced interface limits. Adjustable output budgets may be raised or split for concrete gaps.

Ask one bundled question when an unresolved choice affects public behavior, persistence, authorization, security, money, destructive effects, compatibility or acceptance. Reuse answers and existing approval. Keep other assumptions narrow, reversible and visible.

For specification, slicing, approval or amendment, read the relevant sections of [references/specification.md](references/specification.md). Proposed or review-pending durable slices remain ineligible despite parent approval. Preserve amendment resets and required independent review. Use [references/intent-interview.md](references/intent-interview.md) for unresolved intent and [references/delivery.md](references/delivery.md) for sustained slices or unresolved coverage. Ordinary implementation uses this entrypoint without default reference reads, extra approval or new documents.

## Choose evidence by risk

Before tests, map acceptance and applicable risks to existing checks in compact working notes or an existing task record. Reuse adequate coverage. Check uncovered behavior, affected regressions and required build/static commands, including applicable:

- Trust boundaries: hostile input, denial before effects, containment and safe errors. At external or injectable boundaries, validate successful outputs against public format, authorization and reporting guarantees before writes or success reports. Returned metadata must agree with committed state. Preserve specified errors and validation order.
- Persistence: validation before writes, preservation/recovery after partial failure and format compatibility.
- Async work: ordering, concurrent ownership, late results, backpressure, cancellation and recovery.

Choose distinct behaviors, validation branches, error precedence, state transitions and plausible failure mechanisms. Retain explicitly required and adversarial cases, boundary values, hostile input classes and distinct async interleavings. Remove only repetition without a distinct requirement or mechanism. Do not cap test counts or substitute counts for coverage.

Negative cases must satisfy earlier preconditions and assert the intended public-contract failure. An unrelated error leaves coverage open. Infrastructure repairs must preserve the invalid input. Construct control-byte test values inside the target program when command transport cannot carry them, preserving the exact tested value and assertion. Establish focused Red when practical. Dependency, compile and timeout failures alone are not Red. Reuse the project harness. Async checks bound the whole lifecycle, assert immediate effects and settle/cancel started work even after assertion failure.

## Implement and close

Prepare missing dependencies once with documented commands. Reuse valid installations through documented no-resolution options. Preserve manifest/lockfiles unless authorized and retain all required setup/check commands. After timeout, inspect readiness and documented cache/environment modes before resolving again.

Make one coherent behavior/test change. Preserve untouched declarations with targeted edits or range formatting, restoring unrelated formatter changes. Inspect hunks against the starting scope/contracts, then run focused and required affected checks. Retain each exit status and stop dependent steps on failure.

Before dispatch, use the supplied interface, literal example and exact payload keys/types. Report sections are not API fields. Resolve consequential interface gaps from authorized documentation/responses. Keep an inner shell command one argument. Serialize for its parser and shell-quote each argument without another shell layer. JSON serialization is not shell quoting. Only confirmed pre-dispatch rejection proves non-execution. Otherwise inspect receipts/state before retrying, retaining failed evidence and permissions.

Observe a running command through its original handle at meaningful intervals. Do independent owner work or wait. A polling timeout does not authorize restart. Classify behavior, environment and evidence failures before changing code.

Plan final required verification to include changed files, whitespace and status in the same permitted command when dependencies and failure ordering are known. Preserve individual results and stop on failure. Reuse matching hunk/check evidence after success. Add checks for edits, failures, explicit policy or a concrete uncovered risk. Retain required results and failed diagnostic evidence, settle async work, then remove only authorized generated files. Known cleanup paths/order need no extra call. Keep cleanup separate after check failure or a new cleanup decision.

## Independent assurance and ownership

Delegate for consequential independent judgment or useful parallel work with separate dependencies and file ownership. Preserve required reviews and challenge for material correctness, security, compatibility and persistence risks. Before optional reservation, name the unresolved question, decision-changing evidence and concurrent owner work. Keep understood bounded work with its owner when handoff adds waiting without needed assurance. A clean review does not prove it was unnecessary.

Confirm worker access before reservation. Tool responses are not automatically shared. Supply actual interacting public guarantees or a contract location accessible to that role, current revision, known paths/tools, question and affected decision, read/write scope and stopping condition. Limit the first source read to needed contracts/code, then request ranges or changed hunks only for a named gap.

For multiple workers or write ownership, read relevant role/ownership sections of [references/orchestration.md](references/orchestration.md). Use its high-risk sequence for consequential closure. Keep one owner for scope, overlapping edits, diagnosis, integration and completion. Use or explicitly reject each contribution. Follow runtime model policy and include workers, failures, waits, review and integration in total cost/time.

Give reviewers the check map: revision, behavior, actual runner and result, with planned checks unverified. Request concrete counterexamples beyond that map. Run owner checks at the source state where results apply. Reuse matching results unless independent execution is required, sources changed, evidence is missing or a counterexample warrants another check. Never attribute owner checks to a reviewer.

Missing worker inputs/rules leave coverage open. Repair authorized handoffs while retaining failed assignment/cost. Accept findings only within demonstrated scope. Incomplete coverage cannot fulfill required review. Worker evidence cannot replace final integrated verification.

Report delivered behavior, actual checks, assumptions and gaps. Distinguish proposed, approved, implemented and runtime-verified work. Unexecuted required checks leave completion open.
