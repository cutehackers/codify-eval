# Codify

Deliver the requested behavior within the original scope. Preserve unrelated work and public contracts. Keep acceptance criteria and their checks compact.

## Resolve the edit boundary

Start with named entry points. Batch repository instructions, dirty status, relevant implementations, contracts, callers and tests in one targeted read when independent. Expand only for a specific unanswered dependency, behavior or decision. Stop discovery once the edit boundary and acceptance checks are understood. Reuse facts already observed.

Resolve policy from repository evidence and current user instructions. Ask one bundled question only for an unresolved choice affecting public behavior, persistence, authorization, security, money, destructive effects, compatibility or acceptance. Preserve the answer and existing authorization. Keep other assumptions narrow, reversible and visible.

Read [references/specification.md](references/specification.md) for requested specification, slicing, approval or amendment work. Proposed or review-pending durable slices remain ineligible even when their parent is approved. Preserve amendment resets and required independent review. Read [references/intent-interview.md](references/intent-interview.md) for unresolved intent. Ordinary authorized implementation needs no new approval or document. Verification and status requests use [references/delivery.md](references/delivery.md) within their requested mode.

## Implement with complete, economical evidence

Before validation, identify applicable checks:

- Observable behavior: public behavioral checks. Shared modules or public contracts also require affected caller regressions and required build/static checks.
- Trust boundaries: invalid or hostile inputs, denial before side effects, safe error output.
- Persistence: validation before writes, preservation and recovery after partial failure. Changed formats also require compatibility checks.
- Async work: relevant ordering, concurrent access, stale results, cancellation and failure recovery.
- Repository policy: required static, build and test commands.

Existing checks suffice when they expose the defect and cover acceptance. Add tests for uncovered risks. Establish focused Red when practical. Compilation, dependency and timeout failures alone are not Red. For controllable futures, assert immediate effects before awaiting potentially stuck work, bound waits and settle pending work in failure-safe teardown.

Make implementation and needed tests one coherent change when dependencies are understood. Inspect the diff for the intended behavior and all needed test insertion before running expensive validation. Group focused and required affected checks in one invocation when useful, retain each exit status and stop on failure. An earlier failing check must never be hidden by a later successful command. Run additional investigation or validation only for changed inputs, a failure or a concrete remaining risk. Preserve original acceptance when diagnosis is difficult.

Read [references/delivery.md](references/delivery.md) for unresolved coverage or sustained slices. Classify behavior, environment and evidence-collection failures before changing code. Economical execution still requires every applicable acceptance and risk check.

## Delegate for a concrete benefit

Keep one owner of scope, overlapping edits, diagnosis, integration and completion. Delegate for consequential independent judgment or useful parallel work with independent dependencies and distinct file ownership. Specify the question, decision affected, boundary, evidence and stopping condition. Read [references/orchestration.md](references/orchestration.md) when delegating. Use or explicitly reject each contribution. Include workers, failures, waiting, review and integration in total cost and time. Follow the runtime model policy.

Inspect the final diff and original acceptance. Report actual behavior, checks, assumptions and gaps. Distinguish proposed, approved, implemented and runtime-verified work. Required checks not executed leave completion open.
